# Data provenance and design decisions

## 1. Real metadata, explicit fictional commerce

Open Library is the free source. The committed snapshot contains 97 edition records imported on 29 September 2026 UTC (30 September in the development timezone). Each has an edition ID, work ID, title, authors, available ISBNs, source URL and retrieval timestamp. Subjects and original publication year originate at work level; they are not guaranteed edition-specific facts. Covers are requested remotely and never required for the UI to function.

The importer makes ten category searches and enriches a small sample of editions, with at least 1.1 seconds between requests. It does not scrape HTML or bulk-harvest the database. Optional runtime lookups are low-volume, cached, identified with a contact email and throttled. Live lookup defaults off: the seed is sufficient for the prototype and isolates demonstrations from source availability. [Open Library API guidance](https://openlibrary.org/developers/api), [search endpoint](https://openlibrary.org/dev/docs/api/search).

The tested legacy batch-book endpoint returned 404, so the importer uses search results with edition IDs plus a small number of direct edition lookups. Most records lack verified binding information. They remain **unspecified**, with a documented fictional $12.99 price. Guessing format from a cover or ISBN would mislead the shopper.

| Edition format     | Fictional unit price |
| ------------------ | -------------------: |
| Verified paperback |               $12.99 |
| Verified hardcover |               $22.99 |
| Verified ebook     |                $7.99 |
| Unspecified        |               $12.99 |

Prices are not market estimates, publisher prices or offers from Open Library. They are static seed values, computed in integer cents. Stock is five copies for normal seeded items and zero for deliberately unavailable examples. Stock is independent per visitor. No tax, delivery fees or discretionary discounts exist. A refresh can change the selected books; prices do not change during a running session unless a new catalogue is deployed, in which case confirmation rechecks totals.

Search-only external books have `stocked:false`, zero stock and no offered price. The UI displays “Not stocked” rather than $0.00. They cannot enter a basket.

## 2. Catalogue quality and licensing

Open Library is community-maintained; subjects, contributor lists and titles can be imperfect. Some work-level authors include translators/narrators or contributors from other editions. The UI links directly to the source edition and does not promise bibliographic perfection. The English UI can display non-English or bilingual source titles.

Broad imported subject categories are not age ratings. A small editorial correction moves teen titles from Children to Young adult, and science-fiction novels from Science to Science fiction. These corrections are recorded in the importer and reproducible. No plots, review snippets or full book text are fabricated to make the sparse metadata look richer. Recommendations grounded only in subjects are necessarily less nuanced; live evaluation should assess that limit.

Open Library says the Internet Archive asserts no new proprietary rights over database material, while existing rights may still apply. The source does **not** justify treating every cover or contributed description as MIT/CC0. This repository includes factual metadata, source attribution and small subject lists, not cover-image files or book text. Remote covers retain their original rights. Fallback cover art is generated by the UI as a plainly decorative title layout. [Open Library licensing statement](https://openlibrary.org/developers/licensing).

## 3. One agent with deterministic commerce

Use a single tool-calling LLM, not a team of agents. The task is one sales conversation with a small catalogue. Extra agents would increase latency, cost and debugging complexity. Direct SDK calls make the tool trace and cost boundary easy to inspect.

Search uses title/author/ISBN/subject matching rather than embeddings. The catalogue is small enough that keyword retrieval and model-guided query refinement are sufficient. This avoids another service and opaque similarity scores. Add embeddings only after evaluation shows that semantic recall is the bottleneck.

The LLM proposes and explains. Application code validates editions, calculates totals, enforces stock, creates quotes and confirms orders. There is intentionally no `confirm_demo_order` model tool, despite that name in the initial tool list: exposing it would make a generated tool call appear to be user authorization. Exact confirmation text or a dedicated UI action is a clearer boundary.

## 4. Model choice and cost

The configured starting model is Claude Sonnet 5.5 through the Anthropic SDK, chosen for conversational quality and tool support without a separate orchestration framework. Model ID and token prices are environment settings, not hardcoded in commerce logic. The documented starting rates were $2/million input tokens and $10/million output tokens when planning; verify them before changing model access or pricing. [Anthropic model reference](https://platform.claude.com/docs/en/models/overview).

No funded API credential was supplied during implementation, so live model access, response quality and token-cost measurements are not claimed. Provider-boundary tests use mocks. Guided offline mode uses explicit rules, is labelled in the UI and is not described as AI.

## 5. Persistence and hosting

Use local PGlite for a no-account developer setup and external PostgreSQL for hosting. Both execute the same migration and SQL. Persist budget accounting rather than putting it in memory: free hosting restarts must not reset the allowance. Production refuses local-only storage.

Free Render hosting is the selected prototype target; the committed blueprint does not silently upgrade plans. Its cold starts are accepted. Neon is the planned free persistent database. Neither a working production database nor a public deployment was claimed during local implementation. [Render free service limitations](https://render.com/docs/free).

## 6. UI delivery deviation

Claude Code was unavailable, but a useful local prototype did not need to wait. The React UI was implemented directly using the agreed API contract and tested on desktop/mobile. `claude-code-ui-brief.md` lets Claude Code refine or replace it later. No claim is made that Claude Code authored the current UI.
